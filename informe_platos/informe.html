Pruebas Estáticas3

Jest + Supertest

Suite backend/test/api/platos.test.js: conexión real a MongoDB Atlas, CRUD completo y validación de respuestas de error.

Éxitos

  1. GET /api/v1/platos: devuelve 200 y una lista JSON.
  2. POST /api/v1/platos: crea un plato válido y devuelve 201.
  3. GET /api/v1/platos/:id: consulta el plato recién creado y devuelve 200.
  4. PUT /api/v1/platos/:id: actualiza nombre y precio, y devuelve 200.
  5. DELETE /api/v1/platos/:id: elimina el plato y devuelve 200.

La suite usa la base de datos real y elimina los documentos creados durante la ejecución para no dejar datos residuales.

Pruebas Estáticas5

Fracasos controlados

Las pruebas de fracaso comprueban que la API rechace las peticiones inválidas y no altere la base de datos.

  1. GET /api/v1/platos/PLA_NO_EXISTE_999: devuelve 404 y success: false.
  2. POST /api/v1/platos con precio: 0: devuelve 400 y el campo precio.
  3. POST /api/v1/platos con CAT_NO_EXISTE_999: devuelve 400 y el campo id_categoria.

Estas pruebas también finalizaron correctamente: el resultado esperado es una respuesta de error, no una excepción.
